# Structured Notes search: isolated hosted experiment

This experiment evaluates the previously reviewed eighteen-file structured-search proposal. It is one step toward the existing goal of complete documented feature coverage and measured improvements. It does not redefine that goal or install the feature into the active product.

The exact push branch is `experiment/notes-structured-search-20261019`. A single new commit must have `2a8482b42784eb262d6d5b82e62d8d1220dc4821` as its parent and change only this package and its new workflow. The hosted Windows 2022 job uses Node 24.16.0. There is no workflow-dispatch assumption, dependency installation, paid resource creation or local execution step.

The collector authenticates all forty-one baseline Notes files, the frozen eighteen payload identities and their source review/license/provenance, the fixed retained original-helper inputs, shared runtime/static dependencies and actual committed experiment sources. It preserves complete selected source contents before composition, after exactly eighteen overlays, and after the test attempt. All forty-six composed Notes filenames are physically enumerated. Product and original code execute only after this authentication, in the hosted runner. The active local forty-one-file epoch and publication source manifest remain unchanged.

The planned finite selection retains all twenty-four existing Notes unit, HTTP and synthetic DOM test files, adds the four already reviewed search files, and adds three real HTTP search scenarios in one experiment-owned module. The exact original comparisons remain forty-eight standalone parser cases and thirty-two metadata predicates evaluated with the original query builder against synthetic SQLite. Parent subtests are counted explicitly in TAP totals; comparison cases are not inflated into full-product results. The collector records actual counts and bounded raw stdout/stderr, including failures, and keeps same-attempt source checks and receipts. Native TAR is mandatory for the retained JEX tests; no fallback can turn missing tooling into a pass.

The frozen proposal adds an explicit Filters mode while preserving the default Text mode. Its metadata and substring matcher is limited. Unsupported queries returning an error are an exposed limitation, not feature parity. The original full application, its persisted search database, FTS behavior, ranking and user interface are not executed by the new search comparisons. Synthetic DOM checks are not real browser acceptance. Performance and usability superiority are not measured here.

## Remaining search work

The complete documented search inventory still includes `any:` combinations, creation/update/due dates and relative-date boundaries, resource/MIME predicates, source URL, record ID and geographic fields, full-text token/phrase/prefix behavior, normalization and multilingual modes, relevance/ranking, database indexing/update consistency and the corresponding UI/documentation workflows. Limits such as length, malformed grammar and wildcard handling must have explicit compatibility contracts. Existing unsupported features remain open after this experiment.

The next backend study must first pin the original query-to-SQL, text normalization, tokenizer and ranking contracts and original database fixtures. Then design the persisted search index and migration, implement the remaining field predicates and combination rules, and compare results through both products' real database paths. Engine choice must follow those contracts rather than assume one SQLite FTS variant is equivalent to another. Index rebuild, editing, deletion/trash, import/export, restart and migration behavior need independent regression evidence.

Later dedicated hosted stages must exercise real Chromium workflows and accessibility, compare original application results on controlled datasets, and measure latency distributions, memory, index/storage cost, startup/rebuild work and reliability under the same workloads. This finite job cannot establish those results. Full documented parity and superiority in speed, resources, usability, compatibility and reliability remain unproven.

The source plan and all receipts distinguish the baseline commit, the new experiment commit, the exact experimental overlay and historical original-source epochs. They never rebind earlier publication receipts to this composition. A successful workflow is a bounded experimental result; independent artifact/source qualification is still required before installation or broader claims.
