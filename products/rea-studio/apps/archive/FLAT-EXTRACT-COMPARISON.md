# Files only extraction comparison scope

These tests are prospective until their exact source is admitted and executed on the supported hosted runner. They add two genuine Chromium cases and a separate four-group original comparison. The existing eleven browser scenarios and the ZIP AES eight-group, 29-command original study remain separate.

The owned corpus contains nested binary, Unicode and zero-byte files, explicit empty directories, fixed file dates and a separate basename-collision archive. Both native and complete original 7-Zip 26.04 writers supply ZIP, 7Z and AES ZIP inputs. Every new original command authenticates the pinned complete executable and paired library before and after execution, retains bounded process observations, and uses private stdin for synthetic passwords.

`Files only` and ordinary `7z e` share the flattened file projection. Their directory policy differs: ordinary `e` processes stored directory entries as basenames; `Files only` skips directory entries. The original `-xtd` switch excludes directory metadata, so `e -xtd` supplies a separate files-only comparison. For a directory-only archive, the pinned original source returns without creating an output folder after `-xtd` selects no entries; this application deliberately creates a new empty destination and reports zero extracted files. Fresh hosted tests must verify these source-based expectations.

Full paths is compared with `7z x` using complete file, directory and file-date observations. A collision is a separate policy comparison: this application refuses all flattened output before creating destination parents, while the original with explicit `-y` may replace an earlier extracted file. No claim that overwrite policies are equivalent is made.

The browser cases use a real application server, real UI-created ZIPs and actual HTTP extraction. Binary input is prepared by the owned fixture filesystem; this does not claim a binary editing UI. Filesystem observers retain restored synthetic bytes and the fixture takes screenshots after password fields clear. No browser download feature, full-product parity, production security proof or universal superiority is claimed.
