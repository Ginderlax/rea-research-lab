# Native generic WebDAV draft

This isolated draft adds a newly written WebDAV client and local-to-WebDAV copy/sync transfer engine. It is not integrated into the frozen REA Studio app. No original executable, original Go runtime or vendor SDK is imported or launched by application code. The existing newly written native filter library is reused byte-for-byte. Full product completeness, full documented-feature enumeration and universal superiority remain false.

## Supported contract

`webdav.mjs` exposes `createWebDAV({endpoint,auth?})` with OPTIONS capabilities, depth-1 `list`, depth-0 `stat`, bounded binary `read`, conditional `write`, ordinary no-body `mkdir`, and conditional file/empty-collection `remove`. Endpoints are HTTPS with normal system TLS verification. Literal loopback HTTP is supported solely for synthetic fixtures. Credentials cannot appear in URLs. Redirects and compressed responses are refused; authentication is never forwarded elsewhere. Anonymous and request-scoped, preemptive UTF8 Basic authentication are supported. Basic interoperability is limited to ASCII credentials or servers accepting UTF8; challenge negotiation, normalization and other authentication schemes are excluded.

The parser supports a bounded UTF8 XML 1.0 subset: ASCII XML names, namespaces, comments, CDATA, predefined/numeric entities and DAV multistatus/response/propstat. It rejects declarations of external entities/DTDs, malformed encodings, contradictory known properties, duplicate/escaping hrefs and incomplete metadata. Only successful property groups contribute known DAV properties. Unknown vendor properties are ignored. Returned resources must remain within the endpoint origin/root and requested depth. Strict IMF-fixdate dates and bounded ASCII ETags are supported, including empty strong ETags. Other original date formats, non-ASCII ETags, Unicode XML names, arbitrary processing instructions, response-level failed entries and vendor quirks are explicit exclusions. Paths use a portable Windows-safe subset; reserved names, ambiguous percent escapes, encoded separators, trailing dots/spaces and aliases are rejected. This is not a complete XML or WebDAV implementation.

`dav-transfer.mjs` exposes `createDAVTransfer(workspace).preview(input)` and `.apply(input)`. Inputs use `source` (existing local workspace directory), `destination` (existing remote collection or blank URL root), `mode` (`copy`/`sync`), `filters`, `comparison`, and request-scoped endpoint/auth. Apply uses the opaque preview token plus fresh endpoint/auth. Sync requires `allowDeletes:true`. `dav-actions.mjs` adds an HTTP-ready action contract and an additional explicit `confirm:true` gate. Its status writes never include credentials. `client-webdav-snippet.mjs` supplies an isolated UI draft that clears passwords after each action, invalidates edited settings, lists remote folders, downloads complete previews and explicitly approves changes. Embed it into the app client on authorized integration; it adds no static browser imports. Its syntax and HTTP action flow are checked; browser rendering has not been checked by this agent.

For pinned rclone **generic `vendor=other`**, default equality uses size because the backend advertises no modification-time precision. `checksum` falls back to size because it advertises no common hashes. The seven supported boolean options are `checksum`, `sizeOnly`, `ignoreSize`, `ignoreTimes`, `ignoreExisting`, `update`, `noUpdateModtime`. Missing destination transfers first; ignore-existing takes precedence over ignore-times; size-only precedes checksum. Update compares times using the original fixed 1-second fallback window, including exact boundaries; older destinations can require upload even with equal size. Source nanoseconds are preserved for exact comparison. Downloaded SHA256 hashes protect preview state and verify bytes; they never change rclone selection decisions. Writable server modification times, refresh-times and user override of this generic fallback window are excluded.

## Safety and recovery boundaries

Preview reads and fingerprints the complete source and destination inventories, including excluded files. Apply repeats both inventories and rejects changes before mutations. Every existing destination file requires a strong ETag, including skipped files, because full destination fingerprints use conditional reads. Existing-file PUT/DELETE and guarded GET use If-Match; new-file PUT uses If-None-Match `*`. Correct server enforcement and authentic strong validators are required; OPTIONS declarations do not prove either. A noncompliant server can still violate these protections. The service serializes operations by refusing concurrent requests instead of retaining queued credential inputs.

Before any mutations, overwritten/removed destination bytes are written into a fresh `.rea-sync-history/dav-<token>/` directory with numbered preimages and a manifest containing their paths, ETags, byte counts and SHA256 hashes. No remote credentials, username, raw headers or authentication body are stored in plans, history, receipts or status. Uploaded bytes are read back and verified. Failures report prior verified operations, recovery paths and whether the current remote mutation may have happened. A consumed plan cannot be reused. Persistence failure reports that remote work completed. Failed PUT never triggers original rclone's unconditional DELETE cleanup, a deliberate safety difference. Original redundant MKCOL requests returning 405 on existing collections are omitted.

There is no whole-folder transaction, automatic rollback, resumable upload, crash-resume engine, cross-process local lock, remote lock protocol or automatic recovery replay. Preimages and manifests remain local for manual inspection; disk space must accommodate retained bytes and no retention-pruning policy is introduced. Manifest updates are ordinary local writes, without a durable atomic-journal guarantee. Directory membership can race on a remote server because a collection ETag does not necessarily cover descendants; transfer sync therefore removes selected files only and preserves empty collections. The standalone primitive permits only empty-collection deletion after a fresh list, but the list/delete interval cannot guarantee against a server-side collection race; do not use it as a concurrent tree transaction. Aliases, junctions, hard-linked source files and special files are refused, but hostile concurrent local path replacement between validation and open is outside this Node/Windows subset.

Credentials exist only in the current action/client scope, are cleared from reachable client state on close and are requested again for apply. JavaScript immutable strings cannot promise physical memory erasure. No credential store is supplied. Password form state is cleared after each UI action; usernames remain in the editable form. No real accounts, passwords, providers or user data were used in verification.

## Resource bounds

One client permits one outstanding request. Each response has a 30-second absolute deadline, 16 KiB parsed-header limit, 2 MiB XML/body limit for metadata, or 64 MiB binary-file limit. Per client scope: 40,064 requests, 512 MiB outgoing file bytes, 32 MiB outgoing metadata bytes, 1 GiB incoming file bytes and 32 MiB incoming metadata bytes. These count received chunks before retaining them, so aggregate metadata padding cannot cause unlimited repeated allocations. Binary responses are buffered; streaming application uploads/downloads are not claimed. Headers are bounded per request; aggregate header traffic is additionally bounded by request count. Maximum accepted file size is enforced even for listings. A single metadata reply can hit its 2 MiB limit before 10,000 entries.

Each transfer has 10,000 combined source/destination entries, 32 levels below each root and 512 MiB combined inventory file bytes; advertised sizes are checked before binary reads. Local directory iteration streams with 32-entry buffers. A 120-second operation guard is checked between work items; one in-flight request can add up to 30 seconds, and filesystem operations are not preemptible. Filter matching has 64 million work units plus the filter library's expansion/rule limits. Input is validated before copying: 128 KiB estimated UTF16 key/text bytes, 4,096 nodes, depth 12, 64 object keys and 256 array entries; accessors, proxies, cycles, hidden/unknown fields, sparse arrays and nonfinite values are rejected. JavaScript property-key enumeration itself creates a temporary key list; the host's bounded JSON body remains the stronger boundary for arbitrary hostile same-process objects.

Local file reads allocate at most their bounded initial size, read fixed chunks and test EOF plus metadata afterward; a concurrently growing file cannot make `readFile` allocate without a bound. File/collection type collisions, including empty source directories, are explicit errors before remote mutations.

One transfer service retains at most 100 private plans, 8 MiB serialized metadata per plan and 32 MiB aggregate serialized metadata. Oldest plans are evicted; 15-minute expiration is cleaned on the next action/cache query or disposal. Actual JS object/clone overhead exceeds serialized size and transient current inventories are additional. Credentials and file contents are not retained in the plan cache. A host must bound the number of service instances and dispose them with workspaces; this draft factory does not claim a global multi-workspace cache cap. New previews and all response objects are independent of private stored records.

## Pinned evidence and exclusions

`webdav-source-references.json` binds complete official rclone source at commit `be8d6044eacb843b74d335db0c5fbe09222031fe` and RFC 4918/9110/7617 text, including full-file SHA256 and exact contract lines. Source files are verification artifacts, never runtime imports. The original executable and archive hashes are authenticated by the independent oracle helper and the preserved ZIP/source-binding receipt.

`oracle-basic.mjs` compares authenticated original recursive listings, binary downloads/uploads, mkdir and file/empty-directory deletion. `oracle-transfer.mjs` compares all 128 combinations of seven comparison flags over 11 cases (1,408 decisions), original dry-run selections against actual original uploads, native previews/actual uploads, complete resulting folder bytes and eight held-out filtered copy/sync folders. The fixture server is independent stdlib code and never imports native client/engine modules. Original execution occurs only in verification helpers, using a private authenticated binary copy, empty private configuration and synthetic loopback Basic credentials. The original-vs-native action comparison counts successful mutations, explicitly excluding original redundant existing-directory MKCOL/405 requests.

OwnCloud, Nextcloud, Fastmail, SharePoint/NTLM, Infinite Scale, token/Bearer/OAuth/Digest/Negotiate/client certificates, redirects, vendor hashes/mtime headers, quota/proppatch/ACL/locks, depth-infinity, remote COPY/MOVE, range/resume/chunked uploads, remote-to-local/multi-remote transfer, mounted filesystems, bisync, provider accounts and universal server conformance remain unsupported. The frozen local Sync implementation is untouched. All-way or all-feature completion gates stay false.

Run `node validate.mjs` in this folder for source-fingerprinted focused tests, original primitive/transfer corpora, resource observations and consolidated receipt. Native resource observations include the independent fixture server and generated corpora in the same Node process; they do not prove comparative speed, RSS superiority or broad server performance.
