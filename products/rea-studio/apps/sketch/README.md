# REA Sketch

Working local development canvas editor. Start REA Studio and open **Sketch**. Draw rectangles, ellipses, straight arrows, text and freehand strokes. Select and drag shapes to move them. Shift-click or drag empty space to select multiple shapes; **Group**, **Ungroup** and grouped dragging operate on the editable selection. A single selected rectangle, ellipse, arrow or text box has a resize handle. Freehand points cannot yet be resized or individually edited. Stroke/fill/text controls apply to the selection. Undo/redo, local save/load/delete, wheel zoom, Pan or Space+drag, Studio JSON import/export, SVG export and native `.excalidraw` import/export are available.

Keyboard controls work while the canvas is focused: Delete/Backspace removes selection, Ctrl/Cmd+A selects all editable shapes, Ctrl/Cmd+G groups, Ctrl/Cmd+Shift+G ungroups, Ctrl/Cmd+Z undoes and Ctrl/Cmd+Shift+Z redoes. Escape cancels a gesture or clears selection. Undo/redo retains up to 100 open-editor checkpoints; it is not persisted across editor reloads.

## Native Excalidraw contract

The compatibility target is the studied **`@excalidraw/excalidraw` 0.18.1** release, tag `v0.18.1`, source commit `a2ec2889babf7d2295469c6d90ebe77fae57df84`. The `.excalidraw` scene envelope is `type: "excalidraw", version: 2` with elements, app state and optional image files. This version number describes the file format, not the npm release.

Native import retains the complete parsed JSON document. An unchanged native export preserves the original values, field ordering, unknown properties, unsupported elements, deleted records, app state, image-file records and custom metadata. Whitespace and numeric lexical spellings are not retained. This is a preservation roundtrip, not a promise that every imported element is rendered. Metadata remains inert JSON: this editor does not execute links/HTML or fetch/decode/render imported images.

Editable projections currently cover unrotated, unlocked rectangles, ellipses, unbound straight two-point arrows, standalone auto-resizing text, and freehand strokes within the editor's limits. The canvas uses plain geometry and a system sans-serif font. Roughness, hatch patterns, opacity, corner styles, native fonts, arrowhead variants and pressure data are retained in native exports but their appearance is approximated in the preview. Bound arrows, container text, non-auto-resizing text, rotation, locked objects, multiline/curved/elbow arrow geometry, diamonds, lines, images, frames and unknown element types are preserved without editable rendering. An always-visible import panel lists unsupported/approximate content and explicitly says the canvas and SVG show editable projections only. Groups containing non-editable records receive an additional warning: group actions affect editable projections only.

Editing a supported projection updates only the changed mapped fields and increments its element version. Geometry-only changes retain native colors and other appearance metadata exactly. Changing text updates both native `text` and `originalText`. Existing freehand pressure metadata survives moves; a point-count change resets unmatched pressures to simulated pressure. Removing an imported editable element exports its original record with `isDeleted: true`; deleting a saved Studio scene removes its local index entry. Unsupported records cannot be replaced by creating a shape with their reserved identifier. Externally bound elements are not recalculated when a supported container moves; this limitation is reported for imported containers with bindings. New shapes export native element fields. A one-point new freehand dot exports two coincident points so the original small-element filter does not discard it.

Native documents are limited to **4 MiB of UTF-8 JSON**, 2,000 element records, 100,000 metadata nodes and nesting depth 30. Editable scenes allow 2,000 shapes, 5,000 text characters or freehand points per shape, 20 group levels, zoom 0.1–5, stroke width 0.1–30, and coordinate magnitude at most 1,000,000. Oversized, non-finite or malformed JSON is rejected. Valid finite geometry outside editable bounds stays preserved and is listed as non-editable. Viewport values may be clamped for the editor, while unchanged export retains original app state. Internal preservation fields in Studio JSON are not a public schema for manually fabricating imported records.

The implementation is original and does not import the historical study's reconstruction or vendor runtime. Primary pinned specifications: [scene JSON schema](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/dev-docs/docs/codebase/json-schema.mdx), [element type definitions](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/element/types.ts), [original JSON import/export](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/data/json.ts), [element restoration](https://github.com/excalidraw/excalidraw/blob/a2ec2889babf7d2295469c6d90ebe77fae57df84/packages/excalidraw/data/restore.ts).

## Current gaps

This is **not a complete Excalidraw replacement**. It lacks native rough/pressure rendering, line/polygon/diamond tools, rotation, snapping, alignment/distribution, layer/order controls, bound-arrow maintenance, rich typography and native text layout, editable images, libraries, live collaboration, encrypted sharing, cloud storage, PNG/clipboard export, embedded-scene images, full mobile gestures and broad accessibility support. Text-box resizing changes selection geometry without font scaling or wrapping. Groups currently support select/move/delete/style operations and nested outer-group removal; they do not provide complete Excalidraw group-edit mode, mixed opaque-record editing or group resizing. No feature parity, universal quality improvement or broad real-world file compatibility has been established.

## Validation and exact original oracle

Run the owned tests from the repository root:

```text
node --test products/rea-studio/apps/sketch/app.test.mjs products/rea-studio/apps/sketch/client.test.mjs products/rea-studio/apps/sketch/vendor-oracle.test.mjs
node products/rea-studio/apps/sketch/vendor-oracle.mjs
```

The core/API suite covers save/reopen/export using the real disk store, unchanged native preservation, selective native edits, arrow normalization, deletion tombstones, unknown image/metadata retention, safe SVG text/freehand output, bounds, malformed documents, reserved identities, groups and undo. Client tests invoke real editor event handlers against a deterministic DOM/canvas stand-in: freehand drawing, grouped moves, undo/redo, native-file import, persistent warnings and saved native roundtrip. These checks do not replace browser usability or accessibility testing.

The test-only original oracle reads the retained original npm archive and development bundle, verifies their SHA-256 digests, and extracts unchanged released helpers into an isolated VM. The application never evaluates vendor code. Six fully specified exported elements cover rectangle, ellipse, straight arrow, two texts and freehand. Original `restoreElement` accepted their individual element data with matching geometry/points; the original local `serializeAsJSON` output round-tripped through this editor, including a fixture with image files and unknown metadata. The original restoration of an edited imported rectangle also preserves custom metadata. The receipt is [results/excalidraw-compatibility.json](results/excalidraw-compatibility.json), with original digests and extracted-helper hashes. Synthetic fixtures are authored in [fixtures.mjs](fixtures.mjs).

**Oracle limits:** `isValidExcalidrawData` is only a permissive envelope predicate and even accepts malformed element contents. It is never treated as full element validation. Individual restoration and local serialization are exercised in isolation with fully specified data, avoiding ambient default/font/binding dependencies. Full `restoreElements`, app-state restoration, import UI, renderer, ordering repair, legacy migrations, binding repair, font metrics and broad real-world native scenes remain untested. If the retained original archive is unavailable, the oracle test explicitly skips; that is not a compatibility pass. No parity conclusion follows from these tests.
