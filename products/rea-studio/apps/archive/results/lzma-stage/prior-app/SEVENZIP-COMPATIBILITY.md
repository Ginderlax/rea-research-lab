# Bounded 7Z compatibility and default-codec research

The working application creates, browses, tests and extracts genuine `.7z` files using Copy or raw DEFLATE. DEFLATE, the application default, produces compressed bytes that the authenticated **complete original Windows x64 7-Zip 26.04** tests and extracts. The interface offers optional solid compression and states the compressed LZMA/LZMA2 limitation. Ordinary original archives created with `-m0=Copy` or `-m0=Deflate` and `-mhc=off` are read in solid/non-solid layouts. Supported DEFLATE encoded headers also exchange with the original. This is a bounded format slice, not complete 7-Zip parity.

The current run passes **68 archive tests, zero failures or skips**, including **26 new 7Z tests**. SHA-256 content, names/types and defined millisecond modification times are compared in both directions; HTTP tests cover create/list/test/extract and reopening after host restart. The original tests and extracts candidate archives, including six method/solid combinations, encoded headers, 129-entry partial metadata bitmaps, and empty streams. Nine additional original fixtures exercise Unicode names, repeated alignment properties and creation/access/modified metadata. Files without a recorded content CRC remain explicitly unrecorded. The browser test created a two-file solid archive of 244 bytes from 6,480 input bytes, listed its CRCs/shared block, and extracted exact bytes to a new folder. Exact hashes, commands, fixture provenance and the screenshot are in `sevenzip-validation.json`.

Methods and container contracts are source-assisted by the retained official SDK docs and a read-only study of the complete 26.04 reader/writer. The application imports only its own container code and Node’s standard raw DEFLATE primitive; it never invokes the original runtime. The original executable is a test oracle extracted from an authenticated installer into an ignored private run folder. The SDK’s public-domain declaration is preserved; the complete product has separate LGPL/restricted components, and no full-product runtime code was adopted. `sevenzip-source-references.json` binds source paths, exact hashes, embedded document editions and line references. SDK format notes still say **18.06**, and the older C decoder document says **9.35**. They are not claims about the complete current GUI or all codecs. The switch manual and actual default archives establish LZMA2 as the current default even though an older general manual page says LZMA.

| Supported contract | Handling |
| --- | --- |
| Signature/start header/next header | Major version 0; real little-endian 64-bit offsets/sizes; mandatory CRCs; exact archive end |
| UINT64 and metadata IDs | All encoded integer lengths, using BigInt before applicable bound checks |
| Folder coder | One simple input/output coder: Copy `00`, DEFLATE `040108`, LZMA2 `21` with uncompressed chunks only |
| Solid substreams | Exact file sizes, applicable folder and individual-file CRCs; shared stored bytes in listings |
| Optional header encoding | One encoded header decoded by a supported simple coder; writer uses DEFLATE |
| Names | UTF-16LE, exact NUL terminators, valid surrogate pairs; bounded safe relative paths |
| Empty files/directories | EmptyStream/EmptyFile bitmaps and file/directory attributes must agree |
| Dates | UTC FILETIME modification time at millisecond precision; creation/access validated but ignored |
| Unknown ancillary metadata | Bounded skip, not preservation; repeated Dummy fields must contain zero bytes |
| Paths/types | Refuse traversal, device/drive/alternate-stream/absolute paths, duplicates/case collisions, file ancestors, anti-items, links and special Unix types |

Bounds: 16 MiB per file, 64 MiB total decoded file bytes or solid folder, 96 MiB container, 16 MiB plain/decoded header, 10,000 entries/folders/pack streams/total substreams, 4,096 UTF-16 code units per name, 128 path components, 100,000 metadata properties and LZMA2 chunks, and a 64 MiB declared LZMA2 dictionary. Direct module input accepts only Buffer/Uint8Array bytes and checks intrinsic byte lengths before copying; cumulative file bytes are checked before each copy. Standard DEFLATE must consume all packed bytes and produce the declared output. LZMA2 stored chunks require an initial reset, valid controls, complete bodies, exact output and the terminator. Any present CRC mismatch, unexplained packed bytes, overlapping ranges, appended archive or trailing data fails before filesystem extraction. Absent optional pack/folder/file CRCs are permitted by the format; their absence is not a content-integrity guarantee.

These are data bounds, **not process-memory isolation**. Solid writing retains the caller’s file bytes, copies into normalized entry buffers, concatenates a solid buffer, retains the compressed buffer and constructs a separate final archive. At the 64 MiB content limit these include up to 64 MiB each of caller, normalized, solid and compressed buffers, plus a final container up to 96 MiB and metadata buffers. Reading retains the archive, the decoded solid buffer and separate copied file substreams (up to 64 MiB for each output representation); a Uint8Array input creates a further bounded archive copy. Encoded headers add decoded header buffers and their copied stream. Native zlib output chunks, allocation overhead, temporary concatenations and buffers awaiting garbage collection add memory beyond those retained copies. There is no fixed peak-RSS ceiling, worker isolation or streaming extraction, and large supported solid inputs can use substantially more memory than their decoded size.

**Explicit unsupported contracts:** compressed LZMA/LZMA2, default original compressed headers/data, multi-coder filter chains/BCJ/BCJ2, complex bindings, Deflate64, PPMd, BZip2, encryption/passwords, external/additional streams, nested header encoding, SFX, split volumes, repair/update/delete/rename, full metadata restoration, full GUI/shell behavior and other platform parity. The module’s LZMA2 stored writer provides uncompressed format exchange and is not offered as a compressed UI method. Default-original fixtures separately prove rejection of the LZMA encoded header and compressed LZMA2 data with a plain header. Full-feature and all-ways acceptance gates remain false.

## Default compressed primitive decision

Four surveys are pinned by immutable commits and document/source SHA-256. No surveyed third-party implementation is imported. Their exact acquisition record is preserved in ignored research, and its hashes/URLs are carried in the source references.

| Primitive | Pinned basis | Fit and remaining work |
| --- | --- | --- |
| Official LZMA SDK 26.04 | Authenticated `lzma2604.7z`; Igor Pavlov public-domain declaration | Raw C LZMA/LZMA2 encoders/decoders. Preferred future path: compile the primitive reproducibly to a bounded portable module and write a small raw-coder adapter. This does not mean using the original application as a wrapper. |
| XZ Embedded | `ae63ae3a36ed01724674e8f3d750dc47bf125410`, 0BSD-style notice | Maintained decoder with raw LZMA2 internally and dictionary limits. No encoder. Public XZ API does not directly supply arbitrary 7Z raw folders; adaptation/build evidence is needed. |
| xz-decompress | `98b3ed6661ac847a55c9722322cb0bca57bafdad`, MIT package metadata | Packages XZ Embedded as WASM for an XZ streaming interface. No encoder or ready raw LZMA/LZMA2 interface; adopting the existing wrapper alone does not solve default 7Z. |
| lzma-purejs | `75ed915fecef42a87abd754efede2271be18c786`, MIT source notices | Raw LZMA1 decoder/encoder streams can support bounded input/output adapters. Decoder resets state per call; it needs separate LZMA2 chunk-state work and a substantial performance/corruption investigation. |
| LZMA-JS | `8f98fe85a1ef78ab6e9d26ab85ce338f50095a23`, MIT | LZMA interface automatically returns text or bytes depending on decoded data. It is not a ready bounded raw LZMA2 adapter. |

The current Node 24.16.0 standard compression library has no LZMA primitive. No C/WASM compiler was found on the current PATH. The preferred next experiment is an explicitly source-assisted SDK build exposing **raw method/properties/input + expected output + maximum dictionary + consumed input**. Its adapter must reject malformed properties, over-budget dictionaries, truncated streams, incorrect reset/state transitions, excess output and unconsumed packed bytes. Acceptance should compare genuine LZMA2 compression and exact recovery against complete 26.04 defaults at all bounded levels, multi-chunk and solid layouts, encoded LZMA headers, random/incompressible and repetitive payloads, mutation/truncation, repeated operations and measured memory/time. A deterministic source/build/license record and independent test evidence are prerequisites to changing the present limitation.
