# Native n8n workflow slice

Automation provides a source-assisted, bounded native workflow implementation. Production modules import standard Node APIs and this application's own code. They do not execute n8n, the study reconstruction, a vendor runtime, arbitrary expressions, or shell commands. The existing custom workflow engine remains available separately. The following native-core checkpoint evidence describes the original five supported node contracts and remains historical; the subsequent Switch 3.4 / Merge 3.2 contracts, input-port/join scheduling, deliberate deviations and current source-bound evidence are documented in [ROUTING.md](ROUTING.md) and the integration section below.

## Authenticated baseline and original execution

The complete [n8n 2.16.0 release](https://github.com/n8n-io/n8n/releases/tag/n8n%402.16.0) is bound to immutable source commit `6eb2d75670b912bdc0274abd73f4f6e8ca8678c6`. The authenticated `n8n@2.16.0` package explicitly depends on `n8n-workflow@2.16.0`, `n8n-core@2.16.0`, `n8n-nodes-base@2.16.0`, and `n8n-editor-ui@2.16.0`. The older study preserved only the workflow component. `n8n-nodes-base@2.15.1` is not the matching nodes package: it binds workflow 2.15.0.

`native-original-acquisition.json` preserves official registry metadata identities, archive SHA256/SHA512 integrity, exact dependencies and the release-tag observation. `native-original-manifest.json` pins four complete archives, nine immutable upstream source contracts, the development dependency lock, and the executed source/dependency file identities. Authentication runs before imports and after comparison tests. Acquisition and comparison must run separately; an acquisition guard prevents starting comparisons while fixture acquisition is underway. Original artifacts remain in ignored `.local/automation-original`, never in the production app's import graph.

The test oracle executes the exact released Manual Trigger, Set V2, If V2 and HTTP Request V3 JavaScript modules at their supported versions. It uses the released Workflow/expression/parameter-default helpers and the core `extractValue` helper. Its small synthetic execution context does not instantiate the complete n8n execution context, scheduler, CLI, database, editor, or service. HTTP passes original request options to independently invoked pinned Axios 1.13.5; the original core HTTP transport helper itself is not executed. Wait executes source-extracted exact released `execute` and `putToWait` method bodies plus released validation helpers in a test-only VM. The complete Wait class, form/webhook dependencies, persistence backend and wait tracker are not executed.

The final focused accounting is **562 original node executions**, comprising **473 exact output matches**, **85 matching rejection outcomes**, **two HTTP comparisons with explicitly normalized transport headers**, and **two deliberate prototype-handling deviations**. The 85 rejections compare whether execution rejects, not exact error types/messages. Full-response HTTP normalization excludes `date`, `connection`, `keep-alive`, `content-length` and `transfer-encoding`; those transport-generated headers are not asserted equal. **Six exact Wait method/output cases** are separate from the node execution total. There are 1,726 original parameter resolutions and 528 original filter extractions. These are synthetic module/helper observations, not complete-product parity results.

## Implemented native contracts

| Area | Implemented behavior | Important boundary |
| --- | --- | --- |
| Workflow JSON | Native `nodes`, name-based `connections`, type/version, positions, parameters, settings and unknown fields survive structural import/export and saving. Unknown nodes/options/connections can be retained. | JSON values are preserved, not original whitespace or a byte-identical file. A preservation result is not an execution claim. |
| Manual Trigger 1 | Emits one empty JSON item on a manual run. | No webhook, schedule, activation or external trigger service. |
| Set 3.4 | Manual assignments, strict JSON raw mode, string/number/boolean/object/array conversions, include-all/selected/except, dot notation, conversion-ignore setting and item pairing. | No JSON repair, binary data or duplicate-item mode. Property grammar is narrower than Lodash. |
| If 2.3 | Native true/false ports, explicit condition options, strict/loose conversion, and/or, string/number/boolean/array/object/any operators and item pairing. | No regex or date comparisons. The stored condition options govern filtering; editor-computed auxiliary settings are not a complete original editor implementation. |
| HTTP Request 4.4 | Seven methods, scalar query/header pairs or strict JSON objects, JSON-object/raw bodies, bounded redirects, JSON/text/autodetect, full response, Never Error, item pairing, timeout and failure/cancel traces. | Authentication is `none`; credential references, embedded URL credentials and sensitive header names cannot execute. GET/HEAD bodies, files/forms, pagination, proxy/certificate options, batching and cookie jars are unsupported. HEAD is compared with explicit text format. |
| Wait 1.1 | Native interval/unit, first-item amount, pass-through items, durable saved continuation, cancellation and resume. Zero intervals also checkpoint. | Interval is 0–60,000 ms. No specified-date, webhook/form/resume-URL modes. Resume after restarting the host begins with the first native API request; opening the native panel performs that bootstrap. |
| Saved execution | Captures a saved revision and full workflow, validates all reachable nodes before execution, records successful/failing invocations, persists status/output/history, and rejects stale saves. | No native Execute Workflow node, arbitrary expressions, retry, Continue On Fail, error outputs, pinned execution data or execution-once behavior. |
| Local editor | Import/download JSON, saved-revision picker, node/connection diagram, metadata-preserving node rename/parameter/position edits, adding supported nodes/connections, preflight issues, run/status/cancel and history. | Diagram uses a readable grid; native positions remain saved metadata, not a draggable original editor layout. |

Whole-value expressions are limited to `={{ $json }}` and bounded `$json` property paths such as `={{ $json.customer.name }}` and `={{ $json.rows[0]["amount"] }}`. Expressions are parsed without evaluation. Interpolation, context/node references, functions, `$now`, provider helpers and code nodes are rejected. Prototype path components and large numeric indices are rejected, including quoted numeric indices. Unreachable unsupported nodes may be saved and exported; reachable unsupported versions/options, enabled retry/error settings, non-main connections and nonzero input indices refuse execution. Known literal unsupported headers/raw paths preflight before effects. Data-dependent URL/header/body/path errors can only be checked once upstream items exist; all requests for a node are prepared before that node sends any request.

The five supported versions are intentionally exact. Other original versions are preserved but cannot execute. Workflow execution settings accept only `executionOrder:"v1"` and preserved timezone metadata. The native engine uses a bounded depth-first queue: each connection delivery invokes a node separately, and each wire gets copied items. Position-based original scheduling, fan-in synchronization, alias/reference semantics and execution order across complex branches have not been compared with the complete runtime. HTTP processes items sequentially; the released original module launches request promises concurrently. This slice does not promise full n8n item-linking or binary behavior. Undefined fields/sparse array values may normalize through the JSON checkpoint, and the complete original persistence serializer is not compared.

Two adversarial Set fixtures deliberately differ. For an input JSON object's own `__proto__` property, the released Set/deepCopy helper in this isolated context changes the output object's prototype and has no own `__proto__` field. This implementation uses own-property definitions, retaining the literal JSON field while keeping an ordinary output prototype. Those cases are deviations, not matches; this observation is not a full-runtime security finding.

## Persistence, redaction and bounds

`native-save/get/list/validate/history/start/run/status/cancel` are separate actions and record namespaces. Saves use optimistic `expectedRevision`; public inputs are bounded and captured before asynchronous work, and returned records cannot alias a shared MemoryStore. `native-list` returns summaries rather than loading every workflow into one response. Run uses the stored revision even if the editor has unsaved changes.

History reads, inactive status reads, timer resume decisions and durable cancellation transitions share the persistence queue. A receipt run caught a synchronization race where status showed completed before history's queued terminal write; that 53/54 run and the historical native server bytes are preserved in `native-validation.json`. The existing restart/history assertion remained unchanged. A subsequent controlled probe found cancellation could return waiting when a Wait checkpoint write was still held. Cancellation now records its intent before awaiting the active operation, invalidates its timer, and durably cancels a settled continuation. Timer identity checks survive asynchronous reads, and rejected individual requests do not poison queue draining during shutdown. Cancellation cannot undo a completed HTTP effect or change an already completed result.

Eight deterministic audit cases hold selected storage reads/writes and exercise a due timer during checkpoint saving, repeated cancellation/history, stale timer/status reads, cancellation before a new active request, disposal with and without cancellation, held final history publication, queued start during disposal, and rejected queued requests followed by restart. They assert no escaped downstream requests, persisted terminal history, and exactly one legitimate restart effect. The final focused run passed 62 tests. Parent browser recovery evidence preceded the history/cancellation corrections and is labeled with its historical server fingerprint; current backend proof comes from the tests.

Wait saves remaining invocations and items and returns immediately. Due continuations can resume automatically while the host stays open, and after a new host's first native API request. A ready/running record encountered after restart becomes interrupted. Host shutdown aborts current HTTP work and retains already-waiting continuations. HTTP effects are not automatically replayed after interruption; a response received immediately before a crash may already have changed its endpoint. No exactly-once or transaction-wide persistence guarantee is made. Malformed persisted continuation/index data fails closed before downstream effects; external filesystem changes and multi-process writers are outside this single-host development contract.

Public status/history and terminal output/trace records redact sensitive keys and bounded observed secret strings, including copied values. Redaction is not encryption, a credential vault, or a guarantee against arbitrary transformations/encodings. Unfinished continuation/checkpoint files retain raw working items locally so execution can continue faithfully. Saved original documents retain supplied literal values. Do not put actual secrets into these test workflows. This slice supplies no execution-secret interface. Oversized redacted outputs may be omitted with `outputsLimited:true`.

Bounds are development limits: 2 MiB workflow JSON; 1 MiB individual value/request/response; 8 MiB combined execution/checkpoint; 100 nodes; 300 connections; 10,000 items/array length; 100,000 visited entries; depth 40; 500 node invocations and 500 HTTP requests per execution; 16 concurrent running/waiting runs; 1,000 saved workflows and 1,000 saved run states; 50 history entries within 12 MiB per workflow. Run-state files are retained up to the count cap, without an automatic deletion interface. Aggregate disk consumption is not a single small quota. HTTP requires an explicit 1–60,000 ms timeout; the released original default is 300,000 ms. Request URLs are at most 8,192 characters, headers 16 KiB total, header values 8,192 characters, and redirects 0–10. The active execution budget is 120,000 ms excluding saved Wait time; checks occur between nodes and bound HTTP timeouts. They do not preempt synchronous work or provide hard real-time guarantees during filesystem/event-loop stalls. No OS process/memory isolation, network allowlist, production security or performance claim is made.

## Validation and remaining work

`native-validation.json` records frozen fingerprints and the final 62/62 focused app tests: 28 existing custom-engine tests and 34 native tests, with zero skips. Native checks include exact source authentication; original module/helper comparisons; real loopback method/body/query/status/timeout/cancel/size tests; HTTP save/revision/restart; saved Wait resume and cancellation; ready/running interruption; malformed continuation rejection; active-run count limits; caller/returned-record mutation; safe prototype handling; public/private module routes; deterministic queue/timer/cancel/history/disposal races; and DOM tests of native import, metadata-preserving rename, saved execution and stale selection/load races. DOM fixtures are not a real browser validation. Root's subsequent browser/combined evidence is separate.

Setup the test-only fixtures with `node products/rea-studio/apps/automation/compare-original.mjs --acquire-only`. The acquisition script authenticates pinned official packages and immutable sources, installs the exact development lock with lifecycle scripts disabled, and never regenerates the pinned manifest. Running it without `--acquire-only` verifies and runs the original comparison files. Missing/changed fixtures fail tests visibly rather than being skipped. A separate fresh development dependency installation was compared with the pinned dependency file identities; its observation is recorded in the receipt.

Full n8n runtime/editor/database orchestration, all native node versions and options, connectors, credentials/OAuth, expressions/code, providers, accounts, queues, native sub-workflows, error workflows, activation, schedules, durable date/webhook/form waits, multi-process recovery, publication/collaboration/enterprise administration and complete original security/performance/accessibility equivalence remain open. The old custom engine's source comparison and historical receipt describe that separate format; native module tests do not retroactively establish those custom contracts as original n8n parity.

## Subsequent Switch/Merge integration

The earlier native-core evidence in this document remains historical. Current Automation additionally supports the bounded Switch 3.4 and Merge 3.2 slice described in [ROUTING.md](ROUTING.md), with all documented released version families and unsupported options enumerated in [routing-contracts.json](routing-contracts.json). The public [strict preservation manifest](results/routing-source-study/preservation-manifest.json) authenticates the pre-integration 25-file production baseline, 29 staged source fingerprints, every exact source/failure/log/receipt in 15 stage runs, 201 selected released package/source/license bytes and the stage browser evidence. The original vendor archive stays local; the runnable application imports no vendor node implementation.

The [first routing integration receipt](results/routing-validation.json) binds its historical source hashes to application/shared-host tests and original comparisons. Switch invokes the authenticated released execute method and expression/filter/cleanup/schema helpers. Merge invokes complete released mode helpers with explicit static parameters and fallbacks, rather than its full class/router/default schema. Seven exact core enqueue-method calls and four extracted waiting-input-drain executions are separate helper observations, not whole released scheduler executions. There are 1,812 exact output comparisons, ten rejection-presence matches, three dangerous-property deviations and 48 non-index-array representation deviations; the latter 61 are not counted as exact matches. Error text/class equality and whole-product parity are not established.

The subsequent [recovery integration receipt](results/recovery-followup/integration-validation.json) binds the current implementation and 15 additional regression groups. It preserves the first routing source and receipt, then verifies pending/join batches against immediate completed predecessor outputs, the active deadline after awaited checkpoint persistence, and cancellation/deadline/per-item timeout checks before native HTTP inputs and redirect hops. Earlier read-only review reproduced an HTTP delivery queued ahead of an unexecuted Merge and a checkpoint delay that allowed a request after the active deadline. The preserved recovery study includes those failures and finite corrected fixtures. Structural queue validation does not authenticate local checkpoints or detect every coordinated trace rewrite; cooperative guards do not interrupt blocked I/O or prove remote effects were cancelled. The current native bounds, explicit unsupported features and full-product gaps still apply.
