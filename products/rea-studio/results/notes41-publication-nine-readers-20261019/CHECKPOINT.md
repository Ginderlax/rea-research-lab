## Source changes and provenance

The historical 937-source reader receives a named context that serves exactly the old shared-host identity from its authenticated physical carrier. File metadata comes from that real carrier. The retained 13 migration routes and 724 other rows describe the historical source view; actual current source bytes are authenticated separately. The original 306 control bodies remain byte-exact. The audit uses a source-only factory and explicit historical projection rows. Each affected delivery row names the physical carrier and retains the original logical path, declared identity, role and epoch, alongside the separately authenticated actual current Git identity. Historical bytes are not reported as current application source. Current producer and control sources remain separately authenticated to avoid a source hash cycle.

The complete new source protocol declares 132 data rows and one separately pinned helper, giving 133 flat source rows. It includes all nine current record consumers, their exact historical carriers, and the additional historical publication-controls carrier. The historical 60-object proof, 64-file and 256-KiB bounds, 12 tooling rows, 95 old artifact roles and 96 total outer roles remain intact. The complete new envelope retains the 8-MiB combined raw-source bound and the distinct helper size bound.

The separate audit prepares a bounded source-context archive containing those 133 rows, the actual current producer and controls, and the immutable module imported by the shared helper: 136 distinct source rows. Its existing standalone workflow and script captures are retained. The audit's unchanged 12-file, 24-MiB total and 4-MiB per-file artifact limits still apply. If all optional diagnostics plus this new role exceed those limits, packaging must fail and label the retained fallback incomplete. Preparing and reading back source bytes does not by itself prove that the complete artifact was uploaded.

These source groups have explicit scopes. The audit context covers its static code imports and declared source data. The publication envelope covers its declared source protocol; it does not claim a standalone copy of every transitive module used by all publication tasks. Broader historical publication-source qualification remains separate, including the existing Sketch verifier and its proof-loader modules.
